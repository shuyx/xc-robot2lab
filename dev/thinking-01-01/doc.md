# FOC 与 MIT 控制关系分析 —— 机械臂抖动根因

## 背景

灵足时代（RobStride）关节模组，驱动方式标注为 FOC（手册 1.4.4）。当前机械臂运行中出现抖动，此前判断为 MIT 模式控制上限已到。本文分析 FOC 与 MIT 控制的关系，评估抖动根因。

## 三层控制架构

FOC 与 MIT 不是同一层面的技术。FOC 是内环，MIT 运控模式是外环：

```text
┌─────────────────────────────────────┐
│  上层决策：MIT 运控模式               │  ← 位置指令 + Kp/Kd + 力矩前馈
│  (CAN 总线，1Mbps，~1kHz 更新率)      │     五元组：pos/vel/Kp/Kd/torque
├─────────────────────────────────────┤
│  中层：速度/位置环                    │  ← spd_kp=2/spd_ki=0.021/loc_kp=30
│  (GD32F103 MCU 内部，远高于 CAN)      │
├─────────────────────────────────────┤
│  底层：FOC 电流环                     │  ← cur_kp=0.05/cur_ki=0.05/cur_filt_gain=0.6
│  (DRV8353 + GD32，25kHz PWM)         │     d-q 轴解耦，矢量控制
└─────────────────────────────────────┘
```

MIT 控制不是换向策略（那由底层 FOC 负责），而是**上层通信协议 + 外环控制模式**。FOC 负责把电流精确控制到 d-q 轴；MIT 运控模式负责给关节发「目标位置 + Kp/Kd + 前馈力矩」。

## 抖动根因分析

"MIT 模式控制上限"本质是以下 4 层瓶颈叠加：

### ① CAN 总线通信带宽瓶颈

灵足运控模式每帧 8 字节，1Mbps CAN 总线理论 1kHz 更新率。而机械臂关节外环需要 5-10kHz 才能实现平滑柔顺控制。CAN 通信瓶颈导致上层指令离散跳动。

对比：MIT Mini Cheetah 原生方案中，关节 PD 控制（loc_kp/spd_kp）在驱动板 MCU 上以 **40kHz** 运行（论文原文数据），CAN 总线只传高层轨迹指令而非 Kp/Kd。灵足让上层通过 CAN 把 Kp/Kd 注入进来，本质上是把外环放在了通信链路上。

### ② 编码器噪声放大

AS5047P 双磁编 14-bit，单圈绝对值。实测分辨率 ≈ 0.022°，低速时 + 9:1 减速比折算后等效分辨率有限。速度估计（mechVel）中编码器噪声占主导 → 微分项输出震荡 → 位置环激励。

### ③ 电流环参数过于保守

| 参数 | 默认值 | 含义 |
|------|--------|------|
| cur_kp | 0.05 | 电流环比例增益 |
| cur_ki | 0.05 | 电流环积分增益 |
| cur_filt_gain | 0.6 | 电流采样滤波系数 |

cur_filt_gain=0.6 代表重度平滑，电流环响应被大幅压低。在需要快速补偿外力（如桌子晃动产生的 moment arm 变化）时，电流环来不及响应 → 外环位置环被动震荡。

### ④ QDD 低减速比的固有问题

9:1 减速比的 QDD 架构，MIT Mini Cheetah 论文称此为「proprioceptive actuation」——电机转子惯量折算到输出端极小。

- 优势：高带宽力控（~100Hz 力控带宽），高冲击缓解能力，无需力矩传感器
- 劣势：任何微小的电流波动 / 编码器噪声 / 传动间隙都直接表现为输出端速度波动

## 宇树方案对比

| | 灵足 RobStride 03 | 宇树 |
|---|---|---|
| 电机架构 | QDD 单级行星 9:1 | 2 级行星减速（更高减速比）|
| 编码器 | 2×AS5047P (14-bit) | 双编码器（规格未公开）|
| FOC | ✅ 内置 | ✅ 矢量 FOC |
| 抖动抗性 | 低（QDD 天生敏感） | 高（高减速比衰减噪声）|
| 力控带宽 | 高（100Hz+） | 低 |
| 可二次开发 | ✅ CAN 协议开放 | ❌ 用户评价极差 |

宇树不抖的核心原因不是"用了 FOC 而你们没 FOC"——你们也在用 FOC，而且 FOC 是底层换向策略与抖动无直接关系。宇树不抖是因为**高减速比** + **双编码器**抑制了电流噪声和编码器噪声向输出端的传导。但代价是丧失力控带宽和回驱能力（冲击缓解指标恶化）。

## 现有路线评估

前馈补偿路线（重力补偿 ✓ → 摩擦补偿 → 动力学前馈）方向正确：

- 前馈直接在内环注入补偿，绕开 CAN 总线的外环带宽瓶颈
- 摩擦补偿直接抵消 QDD 齿轮减速器的 stiction 效应，消除低速爬行
- 动力学前馈可以在 GD32 MCU 本地闭环，不依赖 CAN 带宽

## 建议下一步

1. **查灵足纯力矩模式**：灵足支持 run_mode=3（电流模式），绕开 CAN 总线的 Kp/Kd 传参，上位机自己做外环，内环只发 iq_ref 电流指令
2. **测编码器噪声**：用示波器看低速段 mechVel 噪声谱，确认抖动频率成分
3. **调参方向**：在稳定前提下逐步降低 cur_filt_gain，提升 cur_kp/cur_ki，争取电流环响应提升 3-5×
4. **评估萝卜派**：LuoboPi / ODrive 能否替代灵足驱动，把控制环全部拿到本地 40kHz 闭环
